# 전설검과 신화검NFT 상세 계획

작성일: 2026-09-15

## 0. 문서의 범위와 현재 상태

이 문서는 앞으로 구현할 기능의 계획입니다. 아래에 적힌 **신규 스크립트·메뉴·컴포넌트·계약 함수는 아직 구현된 것이 아닙니다.** Codex가 해당 단계의 코드를 작성하고 준비됐다고 안내한 뒤 사용자 설정을 진행합니다. 예상 이름은 구현 시 최종 이름과 연결표로 확정합니다. 제공되지 않은 코드나 함수를 직접 만들어 넣을 필요는 없습니다.

현재 프로젝트는 `C:/Users/PC/Desktop/blockChianMarket/MarketPlaceUGS-main`이며, 기존 거래소를 복사한 `Assets/Scene/1.unity`를 계속 사용합니다.

현재 확인된 기능:

- Unity Play 모드에서 Reown을 통해 휴대폰 MetaMask 연결
- Sepolia ETH로 10,000골드 구매
- 서버에서 입금 확인 후 UGS COIN 자동 지급
- 재로그인 후 20,200골드 유지

처음 결제는 한도 문제 이후 수동 복구했고, 다음 결제는 자동 지급을 확인했습니다. **기존 골드 구매 기능과 완료된 결제 기록은 보존합니다.** 새 기능 때문에 `state`를 초기화하거나 기존 `Mkt_*`를 일괄 교체하지 않습니다.

### 만들 기능

| 구분 | 전설검 | 신화검NFT |
|---|---|---|
| 의미 | 일반 게임 아이템 | Sepolia 블록체인의 NFT |
| 얻는 방법 | Sepolia ETH로 구매 | 쿠폰으로 NFT 발행 |
| 소유 기록 | UGS 인벤토리 | NFT 계약에 기록된 지갑 소유권 |
| 게임 리소스 ID 제안 | `LEGENDARY_SWORD` | `MYTHIC_SWORD_NFT` |
| 게임에서 사라지는 조건 | 일반 판매·소모 규칙 | 지갑이 해당 NFT를 더 이상 소유하지 않음 |
| 기존 거래소 판매 | 기존 방식에 맞춰 지원 | 첫 버전에서는 금지, 지갑 간 전송으로만 이전 |

신화검NFT의 UGS 항목은 NFT의 복제품이나 별도 소유권이 아니라 **현재 게임에서 사용할 수 있음을 표현하는 연동 항목**입니다.

- 어떤 코드가 로컬 테스트만 됐고 어떤 기능이 실제 지갑으로 검증됐는지 구분해 보고

### 사용자가 할 일

- UGS Dashboard의 리소스 등록·설정·Publish
- 배포용 파일 전체 복사 및 지정된 스크립트에 붙여넣기

개인 키·복구 구문은 대화에 붙여넣지 않습니다. Codex에는 공개 주소·계약 주소·거래 해시·비밀을 제외한 오류만 전달합니다.

## 2. 먼저 준비할 것

### 사용자: 작업 전 준비

1. Unity Play를 종료합니다.
2. Scene 1에서 Ctrl+S로 저장합니다. 장면 이름 뒤 `*`가 없어졌는지 확인합니다.
3. 프로젝트와 기존 Cloud Code를 백업합니다. 최소한 `Assets`, `Packages`, `ProjectSettings`, `CloudCode`를 보관합니다. `Library`는 재생성되는 캐시이므로 필수 백업 대상은 아닙니다.
4. UGS Dashboard에서 현재 게임 프로젝트를 선택합니다. 현재 화면의 프로젝트 이름은 `multiFpsSample`이지만 실제 연결된 프로젝트 ID가 기준입니다.
5. 환경 선택이 `production`인지 확인합니다. 다른 환경에 Publish하면 게임에 적용되지 않습니다.
6. Cloud Save의 `simple_market/state`와 `config`를 읽어서 별도 파일로 백업합니다. **원본을 삭제하거나 초기값으로 덮어쓰지 않습니다.**
7. COIN 최대 잔액이 다음 구매 금액을 수용할 만큼 크고 변경이 Publish됐는지 확인합니다. 현재 계획의 한도는 1,000,000입니다.
8. 테스트 계정과 지갑을 구분해 기록합니다.

| 역할 | 용도 | 준비 방법 |
|---|---|---|
| 게임 계정 A + 지갑 A | 구매·쿠폰 수령·NFT 전송 | 현재 구매자 계정 활용 가능 |
| 게임 계정 B + 지갑 B | NFT 수신 후 게임 반영 확인 | 별도 게임 계정과 별도 지갑 |
| 상점 수신 지갑 | 전설검·골드 구매 대금 수신 | 현재 사용 중인 판매자 지갑 재사용 |
| 계약 관리자 지갑 | NFT 계약 배포·권한 관리 | 수업용 별도 계정 권장 |

일반 아이템 결제는 게임 계정 확인용 data를 포함합니다. **상점 수신 계정이 구매용 MetaMask에 등록되어 있으면 MetaMask가 거부할 수 있으므로**, 현재 성공한 별도 지갑 구성을 유지합니다.

### 사용자: 이미지 준비

- 전설검 PNG 한 개, 신화검NFT PNG 한 개를 준비합니다.
- 투명 배경 이미지를 사용하면 기존 인벤토리와 맞추기 쉽습니다.
- Unity Project 창에서 `Assets` 아래 적절한 아이콘 폴더에 넣습니다.
- 이미지를 선택하고 Inspector에서 Texture Type을 `Sprite (2D and UI)`로 설정한 뒤 Apply합니다.
- NFT 메타데이터용 이미지는 나중에 별도 공개 저장소에도 올립니다. Unity 안에 넣었다고 인터넷에서 접근 가능한 주소가 생기는 것은 아닙니다.

## 3. 1단계 — 일반 전설검 Sepolia 구매

### Codex 구현

1. 기존 `Gold_GetQuote`·`Gold_Claim`과 전설검 결제를 구분합니다.
2. 예상 신규 서버 함수는 `Sword_GetQuote`, `Sword_Claim`입니다.
3. 전설검 가격은 우선 0.0001 Sepolia ETH로 제안합니다. 최종 가격은 구현 전에 확정합니다.
4. 상품 ID가 포함된 결제 메모를 사용합니다. 과거 골드 영수증으로 전설검을 청구할 수 없게 합니다.
5. 입금 주소·금액·체인·게임 계정·확인 수를 검증합니다.
6. 지급 전 Economy에 아이템 설정이 존재하는지 확인합니다.
7. 거래 해시에 대응하는 안정적인 인벤토리 인스턴스 식별자를 사용하고, 중복 요청·응답 유실 시 재지급 여부를 안전하게 판단하도록 설계합니다. 실제 Economy SDK의 중복 ID 동작을 먼저 검증합니다.
8. 기존 골드 결제의 보류 기록과 전설검 보류 기록을 구분하거나 상품 ID를 함께 저장합니다.
9. 전설검 버튼, 결제 결과, 인벤토리 갱신을 연결합니다.
10. 기존 아이템 목록·아이콘 매핑·서버 허용 목록을 조사해 전설검 표시·판매를 지원합니다.

### 사용자: Economy 리소스 등록

1. 브라우저에서 Unity Dashboard를 엽니다.
2. 현재 프로젝트와 `production` 환경을 선택합니다.
3. 왼쪽 Economy → Configuration으로 이동합니다.
4. `Add Resource`를 누릅니다.
5. 종류는 **Inventory Item**을 선택합니다. Currency가 아닙니다.
6. 이름에는 `전설검`, ID에는 `LEGENDARY_SWORD`를 입력합니다. ID는 코드와 일치하도록 대문자·밑줄 그대로 입력합니다.
7. 저장합니다. 가격 입력 필드가 없어도 정상입니다. 이번 가격은 결제 서버 설정에서 관리합니다.
8. Configuration 목록에 전설검이 생겼는지 확인합니다.
9. Publish를 누르고, 확인창이 있으면 마지막 확인까지 완료합니다.

### 사용자: 서버 코드 배포

아래는 Codex가 전체 파일을 제공한 뒤 실행합니다.

1. Cloud Code → JS 스크립트에서 `Sword_GetQuote`를 새로 만듭니다.
2. 제공된 **전체 복사용 TXT**를 메모장으로 엽니다.
3. 파일 전체를 Ctrl+A → Ctrl+C로 복사합니다.
4. Dashboard 코드 영역 안을 클릭하고 Ctrl+A → Backspace로 기본 코드를 완전히 비웁니다.
5. Ctrl+V로 붙여넣습니다. 변경 비교 화면이나 대화의 일부 코드만 복사하지 않습니다.
6. 첫 줄의 배포 버전 표시가 안내된 값과 같은지 확인합니다.
7. 지정된 파라미터를 등록합니다. 견적 함수는 기본적으로 없음, 지급 확인 함수는 `tx_hash / String / Required`를 예상합니다. **실제 제공되는 파라미터 표가 최종 기준**입니다.
8. Save Script → Publish Version을 실행합니다.
9. Version 목록에서 최신 Live 버전을 열어 새 코드가 들어 있는지 확인합니다.
10. `Sword_Claim`도 같은 방식으로 등록합니다.
11. `Gold_*`와 기존 `Mkt_*`는 지정된 변경이 없으면 건드리지 않습니다.

### 사용자: Scene UI 연결

1. Play를 끄고 Scene 1을 엽니다.
2. 기존 WalletPanel 아래 전설검 구매 버튼을 추가합니다.
3. 기존 골드 버튼을 복제했다면 이름을 `BuyLegendarySwordButton`, 표시 문구를 `전설검 구매`로 바꿉니다.
4. 복제된 On Click 이벤트가 남아 있지 않은지 확인합니다. 자동 연결 코드를 사용할 때는 수동 이벤트를 중복 등록하지 않습니다.
5. Codex가 제공할 최신 자동 연결 메뉴를 실행하거나 연결표대로 해당 Button을 Inspector 필드에 드래그합니다.
6. 아이콘 연결표의 전설검 칸에 준비한 Sprite를 넣습니다.
7. 버튼이 기존 골드 버튼과 겹치지 않도록 배치하고 Ctrl+S로 저장합니다.

### 사용자: 검증

1. 구매 전 골드와 전설검 개수를 적습니다.
2. Play → 로그인 → 지갑 연결 → 전설검 구매를 누릅니다.
3. MetaMask에서 Sepolia, 금액, 수신 주소를 확인하고 승인합니다.
4. 입금 확인 완료 후 전설검이 정확히 1개 생기는지 확인합니다.
5. 골드는 변하지 않아야 합니다.
6. 확인 버튼을 다시 눌러도 검이 추가되면 안 됩니다.
7. 재로그인 후 검이 남는지 확인합니다.
8. 별도 골드 구매도 검증하여 기존 기능이 유지되는지 확인합니다.

## 4. 2단계 — 신화검NFT 계약과 메타데이터

### Codex 구현

- OpenZeppelin ERC-721 기반의 전송 가능한 신화검NFT 계약 작성
- 토큰별 고유 ID, 소유자 조회, 게임에서 보유 목록을 찾을 수 있는 기능
- 관리자용 테스트 발행과 쿠폰용 발행 권한 분리
- 수신 주소·계약·체인·기한·발급 ID에 묶인 서명 검증
- 같은 발급 ID는 한 번만 사용 가능하도록 계약에 기록
- 이벤트로 발행·이전 결과 조회 가능하게 구현
- 발행 제한, 잘못된 서명, 만료·중복 청구, 전송 테스트
- 배포 코드·컴파일러 버전·생성자 입력값·함수 입력표 제공

계약 주소와 tokenId의 조합이 신화검NFT의 신원입니다. 이름이 같은 외부 NFT는 인정하지 않습니다.

### 사용자: 이미지와 메타데이터 공개

1. Codex가 사용할 저장 방식과 파일을 확정한 뒤 해당 저장소 계정을 준비합니다. 수업용으로 IPFS 고정 저장 또는 공개 HTTPS 저장소를 사용할 수 있습니다.
2. 신화검NFT 이미지를 업로드하고 주소를 확보합니다.
3. Codex가 작성한 JSON의 `image`에 그 주소가 들어 있는지 확인합니다.
4. JSON도 업로드해 metadata URI를 확보합니다.
5. 다른 브라우저에서 로그인 없이 이미지와 JSON을 읽을 수 있는지 확인합니다. IPFS URI는 대응 게이트웨이에서도 확인합니다.
6. 이미지 주소와 JSON 주소를 혼동하지 않습니다. 계약의 tokenURI에는 보통 **JSON 주소**가 들어갑니다.
7. 로컬 `C:/...` 경로나 로그인해야 열리는 파일 공유 주소는 사용하지 않습니다.

### 사용자: Remix 배포

이 단계는 계약 파일과 정확한 입력표가 제공된 뒤 진행합니다.

1. 관리자 MetaMask에서 **Sepolia**를 선택하고 테스트 ETH 잔액을 확인합니다.
2. 공식 Remix `https://remix.ethereum.org`를 엽니다.
3. 새 Solidity 파일을 만들고 제공한 계약 전체를 붙여넣습니다.
4. Solidity Compiler에서 Codex가 지정한 버전을 선택하고 컴파일합니다.
5. Deploy & Run Transactions에서 MetaMask를 사용하는 브라우저 지갑 연결 환경을 선택합니다. 실제 명칭은 Remix 버전에 따라 다를 수 있으므로 당시 화면 기준으로 안내받습니다.
6. MetaMask 연결 요청을 승인합니다.
7. 배포 계정과 네트워크가 관리자 계정·Sepolia인지 확인합니다.
8. 계약 이름을 선택하고 제공한 생성자 입력표의 값만 입력합니다. 개인 키는 생성자 입력값이 아닙니다.
9. Deploy를 누르고 MetaMask에서 가스비를 확인한 뒤 승인합니다.
10. 완료되면 계약 주소와 배포 거래 해시를 기록합니다. 이 공개 값은 Codex에게 전달해도 됩니다.
11. 탐색기에서 배포 성공을 확인합니다.

### 사용자: NFT 하나로 기본 동작 확인

1. 관리자 전용 테스트 발행 함수에 수신 지갑 공개 주소와 지정된 메타데이터 값을 입력합니다.
2. 발행 거래를 승인합니다.
3. 발행된 tokenId를 기록하고 계약 소유자 조회 결과가 수신 주소인지 확인합니다.
4. MetaMask NFT 목록에 자동 표시되지 않으면 해당 네트워크에서 NFT 가져오기 기능으로 계약 주소·tokenId를 입력합니다. 실제 표시 지원과 UI는 사용 중인 지갑 버전에서 확인합니다.
5. 이미지가 안 보일 경우 소유권과 메타데이터 표시 문제를 구분합니다. 다시 발행부터 하지 않습니다.

배포와 관리자 테스트 발행의 가스비는 관리자 지갑이 냅니다. NFT를 단순히 받기만 하는 지갑은 수령 승인을 할 필요가 없습니다.

## 5. 3단계 — 게임 계정과 지갑 소유 확인

### Codex 구현

1. UGS 로그인된 플레이어를 기준으로 일회용 서명 메시지를 생성합니다.
2. 지갑 주소·서비스 정보·체인·nonce·기한을 검증하는 방식으로 서명을 확인합니다.
3. 검증된 지갑과 UGS 계정의 연결 기록을 서버 전용 데이터에 저장합니다.
4. 첫 버전은 일반 MetaMask EOA를 지원 대상으로 명시합니다. 스마트 계정 지원은 별도 검증이 필요합니다.
5. 한 지갑을 여러 게임 계정에 동시에 연결하지 못하게 합니다.
6. 지갑 변경 시 이전 NFT 권한을 정리하고 새 지갑의 소유권을 검증합니다.
7. 이후 로그인에서는 저장된 검증 주소를 사용해 읽기 전용 NFT 조회를 자동 수행합니다. 지갑 변경·만료 정책에 따라 재서명이 필요한 경우에만 요청합니다.

### 사용자: 첫 연결 실습

1. 게임 계정 A로 로그인합니다.
2. 지갑 연결 버튼으로 지갑 A를 연결합니다.
3. 새로 제공되는 지갑 소유 확인 요청을 진행합니다.
4. MetaMask에 표시되는 메시지가 게임 연결 목적이며 올바른 주소인지 확인하고 서명합니다.
5. 게임에 `지갑 등록 완료`가 표시되는지 확인합니다.
6. 게임 계정 B에서도 지갑 B로 반복합니다.
7. 주소만 복사해 다른 계정의 지갑을 등록하려는 요청은 서버가 거부해야 합니다.

메시지 서명과 NFT 발행 거래는 다릅니다. 일반적인 소유 확인 메시지 서명은 송금이 아니며 가스비가 들지 않습니다.

## 6. 4단계 — 쿠폰으로 신화검NFT 발행

### 수업용 기본안

쿠폰은 무료이고 **수령자가 발행 가스비만 Sepolia ETH로 부담**합니다. 운영 서버는 발급 허가를 서명하지만 블록체인 거래를 직접 보내지는 않습니다. 운영자가 가스비를 부담하는 대리 발행 방식은 다음 확장으로 둡니다.

### Codex 구현

1. 임의의 일회용 쿠폰 생성 도구를 만듭니다. 쿠폰 원문은 서버 로그·공개 Game Data에 보관하지 않습니다.
2. 서버가 유효성·사용 여부·계정·지갑 연결을 검증합니다.
3. 검증된 쿠폰을 해당 지갑과 발급 ID에 예약합니다.
4. 수신 지갑·발급 ID·만료시간·체인·계약 주소에 묶인 발급 허가를 서명합니다.
5. 클라이언트는 허가를 계약에 제출하고 MetaMask로 거래를 승인합니다.
6. 계약이 중복 사용을 거부하고 NFT를 발행합니다.
7. 서버는 발급 ID와 체인 결과를 확인해 쿠폰 사용 완료를 기록합니다.
8. 사용자가 승인을 취소하거나 앱을 닫아도 새 발급 ID를 무작정 만들지 않습니다. 같은 예약으로 조회·재개합니다.
9. 서버 키·쿠폰 데이터는 클라이언트에서 읽을 수 없게 합니다. Unity 빌드·Git·Default Game Data에 비밀 키를 넣지 않습니다.

UGS Cloud Code에서 서명·암호 라이브러리와 비밀 저장을 사용할 수 있는지 Codex가 실제 환경에서 먼저 검증합니다. 지원이 부족하면 HTTPS 발급 서버를 추가합니다. 이때 서버는 Unity가 보낸 playerId를 그대로 믿지 않고 UGS 인증을 검증해야 합니다. **추가 서버가 필요한지 결정되기 전에 사용자가 호스팅을 구매하거나 임의의 API를 만들 필요는 없습니다.**

### 사용자: 서버 비밀 설정

1. Codex가 확정한 서버 환경의 설정 화면을 엽니다.
2. 발급 서명 전용 키를 안내된 Secret 항목에 등록합니다. 일반 문자열 설정이나 공개 데이터 칸과 혼동하지 않습니다.
3. 그 키의 공개 주소를 계약의 허가된 서명자에 설정합니다.
4. 계약 주소·Sepolia RPC·메타데이터 URI 등 공개 설정을 입력합니다.
5. 서버를 배포합니다. 키 값은 캡처하거나 대화로 보내지 않습니다.

### 사용자: 쿠폰과 UI 준비

1. 제공된 관리자 도구로 테스트 쿠폰 2개를 생성합니다.
2. 쿠폰은 학생별 한 개씩 배부합니다. 공통 고정 문자열을 무제한 발급 코드로 쓰지 않습니다.
3. Scene 1에 쿠폰 입력창과 `신화검NFT 받기` 버튼을 배치합니다.
4. Codex 연결표대로 입력창·Button·상태 Text를 연결합니다.
5. Ctrl+S로 저장합니다.
6. 게임 계정 A와 지갑 A를 연결한 뒤 테스트 쿠폰을 입력합니다.
7. 받기 버튼을 누르고 MetaMask에서 **가스비가 있는 NFT 발행 거래**를 승인합니다. 상품 가격은 무료인 기본안입니다.
8. 완료 후 계약 주소·tokenId·발행 거래 해시를 확인합니다.
9. 같은 쿠폰을 다시 입력해도 NFT가 추가 발행되지 않는지 확인합니다.

## 7. 5단계 — 로그인 시 신화검NFT 자동 표시

### Codex 구현

- 로그인 후 등록 지갑의 지정 계약 보유 목록 조회
- 확인된 블록을 기준으로 일관된 소유권 조회
- 신화검NFT 한 개당 UGS 연동 항목 한 개 생성
- 항목에 체인·계약 주소·tokenId·NFT 연동 출처 기록
- 기존 동일 항목이 있으면 중복 지급하지 않음
- 계약 전체 보유 목록 조회가 완성된 경우에만 삭제 판단
- 동시에 로그인하거나 새로고침해도 추가·삭제가 충돌하지 않도록 플레이어별 동기화 처리
- UI에 `NFT 확인 중`, `동기화 완료`, `조회 실패`를 구분해 표시
- 자동 동기화에 더해 `NFT 새로고침` 버튼 제공

### 사용자: UGS 아이템 등록

1. Economy → Configuration → Add Resource를 누릅니다.
2. Inventory Item을 선택합니다.
3. 이름은 `신화검NFT`, ID는 `MYTHIC_SWORD_NFT`로 입력합니다.
4. 저장 후 Publish합니다.
5. 지정된 새 Cloud Code만 전체 교체 방식으로 등록·배포합니다.
6. Unity의 아이콘 연결 필드에 신화검 Sprite를 넣습니다.
7. 서버 설정에 **직접 배포한 계약 주소와 Sepolia 네트워크**가 들어 있는지 확인합니다.

### 사용자: 로그인 확인

1. NFT가 지갑 A에 있는 상태에서 게임을 종료합니다.
2. 다시 게임 계정 A로 로그인합니다.
3. 소유권 확인이 완료될 때까지 기다립니다.
4. 인벤토리에 `신화검NFT #번호`가 나타나는지 확인합니다.
5. 로그아웃·로그인을 반복해도 같은 번호가 여러 개 생기면 안 됩니다.
6. NFT가 없는 계정 B에서는 나타나지 않아야 합니다.

UGS에 아이템을 추가하는 기능만으로 검의 공격력·전투 효과가 생기지는 않습니다. 이번 범위는 인벤토리 표시와 사용 권한이며, 실제 전투 코드가 있다면 장착 검증 연결을 별도로 수행합니다.

## 8. 6단계 — 다른 지갑으로 전송 후 회수·지급

### Codex 구현

1. 지갑 A가 더 이상 보유하지 않는 NFT에 대응하는 연동 항목만 삭제합니다.
2. 장착 기능이 있다면 서버에서 장착도 해제합니다.
3. 일반 전설검이나 골드로 산 아이템은 삭제하지 않습니다.
4. 지갑 B가 보유한 NFT는 계정 B 로그인 시 추가합니다.
5. 조회 실패·RPC 지연은 `NFT 없음`으로 취급하지 않습니다. 확인 전에는 필요한 기능을 일시 제한하고 다시 조회합니다.
6. 첫 버전은 로그인 및 새로고침 시점에 반영합니다. 접속 중 전송 즉시 반영을 보장하지 않습니다. 실제 전투 사용까지 확장하면 장착·전투 진입에도 서버 소유권 확인을 추가합니다.
7. 신화검NFT의 기존 UGS 거래소 판매·가챠 소모·일반 삭제 요청을 서버에서도 차단합니다. 버튼만 숨기는 것으로 끝내지 않습니다.

### 사용자: 두 계정으로 전송 실습

1. A와 B의 게임을 종료해 첫 테스트 조건을 단순하게 만듭니다.
2. 지갑 B의 공개 주소를 복사합니다.
3. 지갑 A에서 해당 신화검NFT의 전송 기능을 엽니다. 지갑 UI가 해당 기능을 지원하지 않으면 Codex가 준비한 전송 화면을 사용합니다.
4. 수신 주소에 B 주소를 넣고 토큰 번호·Sepolia 네트워크를 확인합니다.
5. A 지갑에서 전송 가스비를 승인합니다.
6. 거래 완료 후 계약의 소유자 조회 결과가 B인지 확인합니다.
7. 게임 계정 A로 로그인합니다. 소유권 동기화 후 해당 번호가 사라져야 합니다.
8. 게임 계정 B로 로그인합니다. 지갑 B가 등록돼 있어야 하며 해당 번호가 나타나야 합니다.
9. A에 있던 일반 전설검과 골드는 그대로인지 확인합니다.

이때 삭제되는 것은 UGS 연동 항목입니다. 블록체인 NFT를 소각하는 작업이 아닙니다.

## 9. 장애가 났을 때 확인할 것

| 증상 | 사용자 행동 | Codex 확인 |
|---|---|---|
| 승인 요청이 안 뜸 | 원래 Console 오류 전체 전달 | SDK 전송 형식·세션·지갑 거부 사유 |
| 입금했는데 대기 | 거래 해시 보관, 재송금하지 않기 | RPC·확인 수·상품·계정 일치 |
| 지급 검토 필요 | state와 잔액·인벤토리 제공 | 실제 지급 결과와 원장 대조 |
| 쿠폰 승인 취소 | 같은 쿠폰으로 상태 확인 | 예약 재개, 중복 발행 방지 |
| NFT가 지갑에서 안 보임 | 계약·tokenId 확인 | 소유권과 이미지 표시 문제 분리 |
| 전송 후 검이 남음 | 전송 해시·동기화 로그 제공 | 확인 블록·계정 연결·삭제 조건 |
| RPC 실패 | 아이템이나 state를 수동 삭제하지 않기 | 부분 조회로 회수하지 않는지 확인 |
| No changes to be published | Live 버전과 파일 첫 줄 확인 | 수정본 동일 여부·환경·버전 비교 |

과거에 수동 복구했던 절차를 다른 결제에 무조건 적용하지 않습니다. 원장을 `GRANTED`로 바꾸는 것은 지급 자체가 아니며, 미지급 확인 없이 잔액을 더하면 중복 지급될 수 있습니다.

- [ ] 기존 10,000골드 자동 구매 및 재로그인 유지

- [ ] 같은 결제 반복 확인 시 중복 지급 없음
- [ ] 골드 영수증을 전설검에 재사용할 수 없음
- [ ] 관리자 외 임의 NFT 발행 거부
- [ ] 쿠폰당 신화검NFT 최대 1개 발행
- [ ] 같은 발급 허가의 재사용·다른 지갑 사용 거부

- [ ] A→B 전송 후 A에서 회수, B에서 표시
- [ ] NFT 조회 실패 시 잘못된 삭제 없음

## 11. 다음 작업의 시작점

먼저 **1단계 전설검 구매만 구현·검증**합니다. 성공하면 NFT 계약 배포로 넘어갑니다. 쿠폰·NFT 동기화까지 한 번에 붙여서 여러 오류를 동시에 추적하지 않습니다.

모든 단계에서 Codex는 `전체 복사용 TXT + 파라미터 표 + Inspector 연결표 + 검증 순서`를 함께 제공합니다. 사용자는 해당 단계의 코드가 준비되었다는 안내 후 설정합니다.

이 문서는 Sepolia 학습용 구현 계획입니다. NFT 발행이 수익·현금 가치·다른 게임에서의 사용을 자동으로 보장하는 것은 아닙니다.
