# 신화검NFT 발행과 쿠폰 지급 — 실제 실행 순서

작성: 2026-09-16

## 0. 이번에 만드는 것

**게임에서 받은 쿠폰을 입력하고 MetaMask에서 가스비를 승인하면, 학생 지갑에 실제 Sepolia 신화검NFT가 생깁니다.** NFT는 다른 지갑으로 전송할 수 있습니다.

이번에 준비한 범위는 계약 배포 → 쿠폰 등록 → 학생 쿠폰 사용 → NFT 보유 확인 → 다른 지갑으로 전송입니다.

**NFT가 게임의 UGS 인벤토리에 자동으로 생기거나 사라지는 기능은 아직 아닙니다.** 그것은 다음 단계입니다. 이번 화면의 “NFT 발행 완료”는 블록체인 발행 완료라는 뜻입니다. 기존 전설검, COIN, Cloud Save 결제 기록과 별개입니다.

원래 계획의 서버 서명 쿠폰 대신 수업용으로 더 간단한 **관리자 온체인 등록 쿠폰**을 구현했습니다. 쿠폰마다 관리자 가스비가 한 번 추가되지만, 서명 서버·비밀 키 저장·서버 운영이 필요 없습니다. 이후 파밍 보상 자동화를 할 때 서버 서명 방식으로 확장할 수 있습니다.

## 1. 아주 쉽게 이해하기

- **계약**: 신화검NFT 소유권을 기록하는 Sepolia상의 프로그램. 한 번 배포합니다.
- **계약 주소**: 이 프로그램의 0x 주소. 판매자 개인 지갑 주소와 다릅니다.
- **tokenId**: 그 계약 안의 검 일련번호. 첫 발행은 1, 다음은 2입니다.
- **쿠폰**: 해당 학생 지갑만 검 1개를 발행할 수 있도록 등록한 코드입니다.
- **관리자**: 계약을 배포한 지갑. 쿠폰 등록과 직접 발행 권한을 가집니다.
- **학생**: 쿠폰을 쓰는 지갑. 수업용 Sepolia ETH가 있어야 발행 가스비를 낼 수 있습니다.

관리자가 쿠폰을 등록할 때는 아직 NFT가 생기지 않습니다. 학생이 쿠폰을 사용한 거래가 성공해야 NFT가 생깁니다. 쿠폰 사용 후 NFT를 다른 지갑으로 보내도 쿠폰이 재사용 가능해지지 않습니다.

## 3. 사용자 준비 — 지갑부터 구분

1. Unity Play를 종료하고 Scene 1을 Ctrl+S로 저장합니다.
2. PC Chrome에 기존 MetaMask 확장 프로그램이 있는지 확인합니다.
3. 계약 관리에 사용할 MetaMask 계정을 하나 정합니다. 기존 판매자 지갑을 사용해도 됩니다. 기존 판매자 수신 설정은 바꾸지 않습니다.
4. 관리자 계정 네트워크를 **Sepolia**로 선택합니다.
5. 배포와 쿠폰 등록을 할 수 있는 테스트 ETH를 준비합니다. 실제 Ethereum 메인넷 ETH를 보내지 않습니다.
6. 학생은 현재 Unity QR로 연결하는 휴대폰 MetaMask 계정을 사용하면 됩니다.
7. 학생 계정도 Sepolia 테스트 ETH를 준비합니다. 쿠폰은 무료지만 가스비가 필요합니다.
8. 관리자와 학생의 **공개 주소**를 메모합니다.

기록 양식:

| 항목 | 기록할 값 |
|---|---|
| 관리자 공개 주소 | 0x... |
| 학생 A 공개 주소 | 0x... |
| 학생 B 공개 주소 — 전송 테스트용 | 0x... |
| 계약 주소 — 배포 후 입력 | 0x... |
| 네트워크 | Sepolia, Chain ID 11155111 |
| 첫 NFT tokenId | 발행 후 확인 |

공개 주소는 공유해도 됩니다. 복구 구문·개인 키는 대화나 프로젝트에 붙이지 않습니다.

## 4. 사용자 — 실습 웹 화면 켜기

이 PC에는 필요한 패키지를 설치했고 계약 빌드도 해두었습니다.

1. Windows 탐색기에서 프로젝트 안 **NFTWorkshop** 폴더로 들어갑니다.
2. 폴더 빈 곳을 우클릭하고 **터미널에서 열기**를 선택합니다.
3. 아래 명령을 입력하고 Enter를 누릅니다.

```powershell
npm start
```

4. 터미널에 `Open http://127.0.0.1:8787` 안내가 나오면 그대로 켜 둡니다.
5. **MetaMask 확장 프로그램이 설치된 PC Chrome**에서 `http://127.0.0.1:8787`로 이동합니다.
6. “신화검NFT 발행 · 쿠폰 실습” 화면이 보이면 성공입니다.

이 주소는 내 PC에서만 접속됩니다. 휴대폰에 이 주소를 입력하지 않습니다. 학생의 휴대폰 지갑은 Unity의 기존 QR 연결을 사용합니다.

터미널을 닫으면 실습 웹 화면의 서버도 종료됩니다. 다시 `npm start`로 켤 수 있습니다.

다른 PC로 복사했거나 node_modules가 없는 경우에만 먼저 아래를 실행합니다.

```powershell
npm ci
npm run build
npm start
```

`npm`을 찾을 수 없다면 Node.js 설치가 필요합니다. 이 PC는 이미 실행을 확인했습니다.

## 5. 사용자 — 신화검NFT 계약 배포

이 방법은 Remix에 코드를 붙여넣을 필요 없이 준비된 웹 화면으로 배포합니다.

1. PC MetaMask를 **관리자 계정**으로 전환합니다.
2. 네트워크가 **Sepolia**인지 다시 확인합니다.
3. 웹 화면 맨 위 **MetaMask 연결**을 누릅니다.
4. MetaMask에서 계정 연결을 승인합니다.
5. 웹에 표시되는 지갑 주소가 관리자 주소인지 확인합니다.
6. **1. 관리자: NFT 계약 만들기** 영역으로 내려갑니다.
7. 최대 발행 개수는 첫 실습에서는 **1000** 그대로 사용합니다. 배포 후 바꿀 수 없습니다.
8. **실습용 내장 메타데이터 채우기**를 누릅니다.
9. 긴 `data:application/json;base64,...` 내용이 메타데이터 칸에 들어가면 정상입니다. 기본 신화검 그림·이름이 포함됩니다.
10. **새 NFT 계약 배포**를 한 번 누릅니다.
11. MetaMask에 계약 배포 요청이 나타납니다. 네트워크와 가스비를 확인하고 승인합니다.
12. 웹의 진행 상태에 거래 해시가 나오면 기다립니다. 승인 수 3개를 기다립니다.
13. **배포 완료**가 나오면 맨 위 **신화검NFT 계약 주소**의 0x 주소를 메모장에 복사해 둡니다.

**여기서 복사할 것은 관리자 지갑 주소가 아니라 계약 주소입니다.** Unity에도 이 계약 주소를 넣게 됩니다.

배포 중 오류·새로고침이 있었다면 무조건 다시 배포하지 않습니다. 진행 상태의 거래 해시로 Sepolia Etherscan에서 성공 여부와 Contract Address를 먼저 확인합니다. 웹은 배포 요청을 받은 계약 주소를 브라우저에 보관합니다.

### 그림을 본인 이미지로 바꾸고 싶은 경우

이번 계약은 배포 시 메타데이터 URI를 고정합니다. 다른 그림으로 바꾸려면 배포 전에 준비합니다.

1. 신화검 PNG를 공개 HTTPS 저장소 또는 IPFS에 올립니다.
2. 아래 형식의 JSON을 만들고 image에 실제 이미지 주소를 넣습니다.

```json
{
  "name": "신화검NFT",
  "description": "Sepolia RPG 수업용 신화검",
  "image": "ipfs://이미지CID",
  "attributes": [{"trait_type":"Rarity","value":"Mythic"}]
}
```

3. JSON 파일도 공개 저장소에 올립니다.
4. 메타데이터 칸에는 **JSON 주소**를 넣습니다. 이미지 주소를 직접 넣지 않습니다.
5. 로그인하지 않은 브라우저에서도 JSON과 이미지가 열리는지 확인합니다.

당장 외부 저장소 가입까지 하고 싶지 않으면 내장 메타데이터로 먼저 진행하세요. 일부 지갑은 내장 SVG 미리보기를 표시하지 않습니다. 그림 표시와 실제 소유권은 별개입니다.

## 6. 사용자 — 학생 A의 쿠폰 등록

1. 웹과 PC MetaMask는 계속 **관리자 계정**을 사용합니다.
2. 맨 위 계약 주소가 방금 배포한 신화검NFT 주소인지 확인합니다.
3. **2. 관리자: 학생 쿠폰 등록** 영역으로 갑니다.
4. 학생 휴대폰 MetaMask에서 수령할 계정의 공개 주소를 복사합니다.
5. 웹의 **받을 학생의 공개 지갑 주소**에 붙여넣습니다.
6. 유효기간은 우선 **7일**로 둡니다.
7. **쿠폰 생성 및 등록**을 누릅니다.
8. MetaMask에서 관리자의 쿠폰 등록 가스비를 승인합니다.
9. **쿠폰 등록 완료**가 나올 때까지 기다립니다.
10. **등록 상태 확인**을 누릅니다. 수령 주소와 유효기간, 아직 발행되지 않았다는 안내가 나오면 정상입니다.
11. **쿠폰 복사**를 누릅니다.
12. 복사한 전체 문자열을 메모장에 보관하거나 학생에게 전달합니다.

쿠폰은 아래처럼 생겼습니다. 줄 전체가 하나의 쿠폰입니다.

```text
MSW1|11155111|0x계약주소|0x학생주소|0x긴랜덤문자열
```

실제로는 각각 완전한 0x 값이 들어 있습니다. 내용을 손으로 바꾸지 않습니다.

### 쿠폰 등록을 실수한 경우

- 등록 승인 전에 취소했다면 초안만 만들어졌을 수 있습니다. **등록 상태 확인**부터 누릅니다.
- 페이지를 닫았다면 **마지막 쿠폰 불러오기**로 같은 브라우저의 마지막 초안을 불러옵니다.
- 학생 주소를 잘못 넣었다면 **이 쿠폰 취소**로 등록된 미사용 쿠폰을 취소하고, 올바른 주소로 새 쿠폰을 만듭니다.
- 이미 사용한 쿠폰은 취소해서 NFT를 회수할 수 없습니다.
- 이 첫 버전에서는 쿠폰 등록 수가 발행 한도를 예약하지 않습니다. 최대 발행 개수를 넘는 쿠폰을 나눠주지 마세요. 한도에 도달하면 미사용 쿠폰도 발행되지 않습니다.

쿠폰을 다른 학생이 보더라도 지정된 학생 지갑이 아니면 사용할 수 없습니다. 사용 거래가 공개돼도 재사용할 수 없습니다.

## 7. 사용자 — Unity에 NFT 패널 만들기

기존 WalletPanel의 골드·전설검 버튼은 그대로 둡니다. 새 패널을 하나 만드는 것이 편합니다.

1. Unity Play를 끕니다.
2. Scene 1을 열고 Hierarchy의 **Canvas**를 선택합니다.
3. Canvas를 우클릭 → **UI → Panel**을 만듭니다.
4. 새 오브젝트 이름을 정확히 **MythicNftPanel**로 바꿉니다.
5. Rect Transform으로 화면의 빈 곳에 배치합니다. 예를 들어 가로 500, 세로 340 정도로 시작합니다. 기존 거래소를 가리지 않도록 실제 Game 화면에서 조정합니다.
6. MythicNftPanel을 우클릭 → UI → **Input Field - TextMeshPro**를 만듭니다.
7. 입력칸 오브젝트 이름을 **NftCouponInput**으로 바꿉니다.
8. 입력칸의 TMP Input Field 컴포넌트에서 Character Limit은 **0**으로 둡니다. 긴 쿠폰을 잘라내지 않기 위해서입니다.
9. 입력칸 폭을 넓게 잡고, 여러 줄 표시를 원하면 Line Type을 Multi Line Newline으로 설정합니다. 쿠폰 자체 중간에 Enter를 넣지는 않습니다.
10. Placeholder 자식의 표시 문구를 “신화검NFT 쿠폰 전체 붙여넣기”로 바꿉니다.
11. 패널 아래 **Button - TextMeshPro** 버튼 세 개를 만듭니다.

| 버튼 오브젝트 이름 | 자식 Text (TMP)의 표시 문구 |
|---|---|
| NftConnectButton | NFT 지갑 연결 |
| NftRedeemButton | 쿠폰으로 신화검NFT 받기 |
| NftCheckButton | NFT 발행 확인 |

12. 패널 아래 **Text - TextMeshPro**를 하나 만듭니다.
13. 텍스트 오브젝트 이름을 **NftStatusText**로 바꿉니다.
14. 상태 텍스트 높이를 넉넉히 잡습니다. 지갑 주소와 tokenId가 여러 줄로 표시됩니다.
15. 버튼의 **On Click()은 비워 둡니다**. 기존 버튼을 복제했다면 따라온 수동 이벤트를 제거합니다.
16. Hierarchy에서 **MythicNftPanel 자체**를 선택합니다.
17. Unity 상단 **Simple Market → NFT - Connect Selected MythicNftPanel**을 누릅니다.
18. Inspector에 Mythic Nft Panel 컴포넌트가 추가되고, 아래 필드가 연결됐는지 봅니다.

| 필드 | 연결할 오브젝트 |
|---|---|
| Wallet | 기존 WalletPanel의 Reown Wallet Bridge |
| Coupon Input | NftCouponInput |
| Status Text | NftStatusText |
| Connect Button | NftConnectButton |
| Redeem Button | NftRedeemButton |
| Check Button | NftCheckButton |
| Rpc Url | 기본 Sepolia RPC 그대로 |

19. Wallet이 비어 있다면 기존 **WalletPanel**을 그 필드에 드래그합니다. Reown Wallet Bridge가 붙어 있어야 합니다.
20. Hierarchy에서 기존 **WalletPanel**을 선택합니다.
21. Inspector의 **Reown Wallet Bridge → Mythic Nft Contract** 칸에 **5단계에서 복사한 NFT 계약 주소**를 붙여넣습니다.
22. 기존 Reown Project ID, Game URL, Icon URL은 바꾸지 않습니다.
23. Scene을 **Ctrl+S**로 저장합니다.

이번 Unity NFT 화면은 **Windows Editor Play + 기존 Reown QR**용입니다. WebGL NFT 사용은 실습 웹 화면으로 제공합니다. 기존 골드·전설검 WebGL 구매 코드는 그대로입니다.

## 8. 사용자 — Unity에서 학생 쿠폰 사용

1. 휴대폰 MetaMask를 **쿠폰에 지정한 학생 A 계정**으로 선택합니다.
2. Sepolia 네트워크와 가스비 잔액을 확인합니다.
3. Unity Play를 누르고 기존 게임 계정으로 로그인합니다.
4. 새 패널의 **NFT 지갑 연결**을 누릅니다.
5. 필요하면 기존처럼 QR을 스캔하고 연결을 승인합니다.
6. 표시된 주소가 쿠폰 수령 주소와 같은지 확인합니다.
7. **NftCouponInput**에 관리자에게 받은 쿠폰 전체를 붙여넣습니다.
8. **NFT 발행 확인**을 한 번 누릅니다. 아직 발행되지 않았다고 나오면 정상입니다.
9. **쿠폰으로 신화검NFT 받기**를 한 번 누릅니다.
10. 휴대폰 MetaMask에서 **가스비**를 확인하고 승인합니다. NFT 상품 가격은 **0 ETH**입니다. 이전 전설검처럼 0.0001 ETH를 판매자에게 보내는 흐름이 아닙니다.
11. Unity에 전송 완료와 거래 해시가 표시되면 잠시 기다립니다.
12. **NFT 발행 확인**을 누릅니다.
13. 아직 발행되지 않았으면 잠시 후 같은 확인 버튼을 다시 누릅니다. 받기 버튼을 연타하지 않습니다.
14. **발행 완료 / tokenId / 현재 소유자**가 나오면 성공입니다.
15. 현재 소유자가 학생 A 주소인지 확인합니다.
16. tokenId와 계약 주소를 메모합니다.

지금은 왼쪽 게임 인벤토리에 신화검NFT 아이콘이 생기지 않는 것이 정상입니다. 이번 단계에서는 지갑에 들어갔는지 확인합니다.

MetaMask에서 거절했다면 발행되지 않습니다. 승인을 눌렀는지 불확실하거나 통신 오류가 났다면 **발행 확인 또는 MetaMask 활동 확인**부터 합니다. 계약이 중복 NFT 발행을 막지만, 이미 사용된 쿠폰을 다시 전송하면 실패 가스비가 발생할 수 있습니다.

## 9. 사용자 — PC 웹 화면에서 대신 쿠폰 사용

Unity UI를 만들기 전에 NFT 기능만 빠르게 확인할 때 사용할 수 있습니다.

1. PC MetaMask를 **학생 계정**으로 전환합니다. 학생 휴대폰의 복구 구문을 PC에 복사할 필요는 없습니다. PC용 별도 학생 지갑을 쓸 경우 그 공개 주소로 별도 쿠폰을 등록하세요.
2. 실습 웹 화면에서 MetaMask 연결을 누릅니다.
3. 계약 주소를 입력합니다.
4. **3. 학생: 쿠폰 사용**에 쿠폰 전체를 붙여넣습니다.
5. **쿠폰 상태 조회**로 지정 주소를 확인합니다.
6. **내 지갑으로 NFT 받기**를 누르고 MetaMask에서 가스비를 승인합니다.
7. tokenId가 표시되면 완료입니다.
8. **내 NFT 목록 조회**를 누르면 보유 tokenId를 볼 수 있습니다.

이미 Unity에서 쓴 쿠폰이면 사용 완료 상태만 조회됩니다. 새 NFT가 추가 발행되지 않습니다.

## 10. 사용자 — MetaMask에서 NFT 보기

1. 수령한 학생 계정에서 네트워크가 Sepolia인지 확인합니다.
2. NFT 탭에서 NFT 가져오기 기능을 찾습니다. 앱 버전에 따라 위치와 명칭이 다를 수 있습니다.
3. Contract Address에는 신화검NFT 계약 주소를 넣습니다.
4. Token ID에는 발행 결과의 숫자, 예를 들어 1을 넣습니다.
5. 가져오기를 완료합니다.

그림이 자동으로 안 뜬다고 미발행은 아닙니다. 내장 SVG나 테스트넷의 자동 수집을 지갑이 지원하지 않을 수 있습니다. 실습 화면의 현재 소유자와 Sepolia 거래 결과로 확인하세요.

## 11. 사용자 — 다른 사람에게 신화검NFT 보내기

### PC 웹 화면을 쓰는 경우

1. 보내는 지갑이 PC MetaMask에 있는 경우 해당 계정으로 연결합니다.
2. 실습 화면의 **내 NFT 목록 조회**로 tokenId를 확인합니다.
3. **전송할 tokenId**에 숫자를 입력합니다.
4. **받는 사람 공개 지갑 주소**에 학생 B 주소를 붙여넣습니다.
5. **NFT 1개 전송**을 누릅니다.
6. MetaMask에서 수신 주소·Sepolia·가스비를 확인하고 승인합니다.
7. 전송 완료 후 학생 B 계정에서 내 NFT 목록을 조회합니다.

### 휴대폰 지갑을 쓰는 경우

MetaMask에서 가져온 해당 NFT의 보내기 기능이 제공되면 수신 주소를 입력하고 전송 승인합니다. 앱에 보내기 기능이 없으면 복구 구문을 옮기지 말고 화면 상황을 알려주세요. 이번 Unity 패널에는 전송 버튼을 넣지 않았습니다.

전송 후 원래 학생 A가 **NFT 발행 확인**을 누르면 “발행 완료” 상태와 함께 **현재 소유자는 학생 B 주소**로 나와야 합니다. 사용한 쿠폰이 원래 지갑에 새 NFT를 발행하지 않습니다.

## 13. 오류별 확인

| 상황 | 확인할 것 |
|---|---|
| MetaMask 연결이 안 됨 | PC 웹은 Chrome 확장, Unity는 Windows Editor QR. 서로 구분 |
| 관리자 계정으로 전환하라는 안내 | 현재 PC MetaMask가 계약 배포 지갑인지 |
| 쿠폰 수령 지갑이 다름 | 쿠폰 등록 주소와 학생이 연결한 지갑 주소 |
| 등록되지 않은 쿠폰 | 관리자 등록 거래가 성공했는지. 쿠폰 초안만 생성했는지 |
| 계약 주소 불일치 | 지갑 주소 대신 실제 NFT 계약 주소를 넣었는지 |
| NFT 조회 형식 오류 | 다른 계약이나 빈 주소, 다른 네트워크 RPC인지 |
| EXPIRED | 유효기간이 지남. 관리자 새 쿠폰 등록 필요 |
| COUPON_UNAVAILABLE | 사용했거나 취소된 쿠폰. 상태 조회 |
| SOLD_OUT | 최대 발행 개수 도달. 한도를 늘릴 수 없음 |
| 가스비 부족 | 승인하는 계정의 Sepolia ETH 확인 |
| 발행 후 게임 인벤토리 비어 있음 | 현재 단계는 정상. UGS 동기화는 다음 단계 |
| localhost 연결 거부 | NFTWorkshop에서 npm start가 실행 중인지 |

오류를 전달할 때 계약 주소, tokenId(있으면), 거래 해시, 오류 문구를 보내주세요. 쿠폰은 대상 지갑이 제한돼 있지만 불필요하게 공개하지 않습니다.

- [ ] NFT를 다른 지갑으로 보내면 현재 소유자가 바뀐다.

## 15. Codex 검증과 남은 것

로컬에서 Solidity 0.8.30, OpenZeppelin 5.4.0, EVM Shanghai로 컴파일했습니다. 로컬 Ganache 블록체인에서 관리자 권한, 쿠폰 등록, 다른 지갑 거절, 중복 사용 거절, 만료, 취소, 직접 발행, 발행 한도, 지갑 간 전송과 소유 목록 변경을 검증했습니다. Node 24의 Ganache 네이티브 모듈 경고는 JS 대체 구현으로 테스트했고 통과했습니다.

Unity 런타임·Editor 코드도 컴파일했습니다. 사용자 MetaMask로 Sepolia 계약 배포와 실제 QR 쿠폰 사용은 아직 실행하지 않았습니다.

다음 단계에서 Codex가 할 일:

1. 서버가 발급한 일회성 메시지에 지갑 서명을 받아 실제 소유자를 검증합니다.
2. UGS 게임 계정과 지갑의 연결 정책을 구현합니다. 주소를 직접 적는 것만으로 연결하지 않습니다.
3. 서버에서 지정한 계약의 NFT 보유 tokenId를 조회합니다.
4. 보유 시 MYTHIC_SWORD_NFT 인벤토리 항목을 생성합니다.
5. 재로그인 시 소유권이 사라졌으면 연동 항목과 장착 상태를 해제합니다.
6. RPC 조회 오류를 소유량 0으로 취급해 삭제하지 않습니다.
7. NFT 연동 항목은 기존 COIN 거래소에서 판매하지 못하게 서버·UI 모두 제한합니다.

이 다음 단계를 구현하기 위해 **실제 배포한 NFT 계약 주소**가 필요합니다.

## 16. 공식 참고와 Remix 대안

- [OpenZeppelin ERC-721](https://docs.openzeppelin.com/contracts/5.x/erc721): NFT 소유권, 발행, tokenURI.
- [OpenZeppelin 권한 관리](https://docs.openzeppelin.com/contracts/5.x/access-control): 관리자 권한.
- [ethers BrowserProvider](https://docs.ethers.org/v6/api/providers/): 브라우저 지갑 연결.
- [Remix 배포 안내](https://remix-ide.readthedocs.io/en/latest/run.html): 브라우저 지갑으로 계약 배포.

로컬 웹 배포 대신 Remix를 사용하려면:

1. 공식 https://remix.ethereum.org 에서 새 Solidity 파일을 만듭니다.
2. NFTWorkshop/MythicSwordNFT_REMIX.sol 전체를 복사합니다.
3. 컴파일러 0.8.30, Optimizer 활성화·runs 200, EVM Shanghai를 선택합니다.
4. MythicSwordNFT를 컴파일합니다.
5. Deploy & Run에서 브라우저 MetaMask 연결 환경을 선택합니다.
6. 계약 목록에서 MythicSwordNFT를 선택합니다.
7. 생성자 admin에는 관리자 공개 주소, uri에는 메타데이터 JSON URI, limit에는 1000을 넣습니다.
8. Value는 0 Wei로 두고 Sepolia에서 배포 승인합니다.
9. 생성된 계약 주소를 로컬 웹의 계약 칸과 Unity Inspector에 입력합니다.

웹 배포와 Remix 배포를 둘 다 할 필요는 없습니다. 하나의 계약 주소를 계속 사용하세요.
